## 1. LESSONS

Durable rules. Each is a rule *because* of the evidence under it. Reusable across every deck we build.

### 1.1 Verification lessons

**L1 — Declared is not loaded. Verify the computed font, never the CSS.**
This deck declared `font-family: Inter` and never loaded Inter. Every slide rendered in system-ui for weeks and nobody caught it by reading the stylesheet. Separately, a first measurement pass returned Georgia's metrics because `Merriweather 700` and `Manrope 600` were still `loading` when it ran.
→ After any font change, assert `document.fonts.check('700 16px <Family>')` for **every declared face**, and measure the advance width of one fixed string at every weight you use. A missing face returns a fallback's metrics silently and passes every build.

**L2 — Shipped is not deployed. `dist/` is the artefact; source is not.**
Fonts landed 17:39. The CSS rewrite landed 17:40. `dist/` was built 16:10. The only woff2 in `dist/assets/` were KaTeX's. The fix existed, was correct, and had never been on screen.
→ Every QC screenshot must come from a build whose mtime is newer than every source file it depends on. Make that a gate assertion, not a habit.

**L3 — Four assertions can go green over four broken frames.**
Slidev clips overflow rather than scrolling, so `scrollWidth` never fires. `Read` renders alpha as a checkerboard. Identical byte counts mean the same file. `curl /` is not a health check. Green is not proof.
→ QC is a *comparison against a named golden by path*, rendered side by side and looked at. "No defects found" is not a verdict.

**L4 — A spec goes stale the moment the deck moves. The gate script is the only requirement that exists.**
`_SPEC_visual_law.md` reports 175 slides, 0 images and a G5 gate of "zero slides with no animation." The deck is 153 slides with 49 `<img>` tags, and `scripts/deck_gate.py` — the gate that actually runs — has no animation gate at all.
→ If a requirement is not in the gate script, it is an aspiration. Put it in the gate or delete it. And chasing 100% animation coverage on 153 slides is itself overdoing it.

**L5 — Notes that assert a fact about the deck rot. Count; don't claim.**
Three separate speaker notes each read "1 of only 3 gold slides in the deck." There are nine `sun` slides. A presenter trusting the note over-invests in the wrong slides and under-invests in the real hinge.
→ Any count in a note must be generated by the stats script, or omitted.

### 1.2 Typography lessons

**L6 — Every `font-weight` you declare must have a physical face, or the browser substitutes silently.**
Shipped: Merriweather 700/900, Manrope 400/600/800. Declared: five sans weights and three serif weights. Measured advance widths proved Merriweather 400 = 500 = 600 = 700 (all land on the 700 face) and Manrope 700 = 800 = 900 (all land on the 800 face). `.sp-h2 { font-weight: 800 }` rendered **byte-identical** to `.sp-h1 { font-weight: 900 }` — the headline/sub-headline hierarchy was carried by size alone. Nearly everything that was not body copy resolved to ExtraBold.
→ Assert `count(distinct font-weight in CSS) == count(@font-face rules)`. Per CSS Fonts L4 §5.2 a request above 500 searches upward first, so the failure always resolves *heavier* — which is exactly why the symptom reads as "loud and undesigned" rather than as a bug.

**L7 — Ship a mid-weight or the deck shouts.**
Authority is a 400/500 body against **one** heavy display. This deck had no mid-weight at all: kicker, card title, name, role, waylabel, quiz number, stat label, chip and the "spoken sentence" tier all rendered at 800.
→ Minimum viable ladder: sans 400 / 500 / 700 / 800 + display 700 / 900. Six faces, no more.

**L8 — A text-optimised typeface used at display size is a different typeface.**
Merriweather is a screen-*text* face. The shipped instance was cut at `opsz=32` and set at 49.6 / 70 / 89.6 / 96px, then fought with `-0.030em` and `-0.04em` tracking that jams already-tight sidebearings. Its variable source carries an `opsz` axis from 18 to 144 — a real display cut existed on disk and was never used.
→ If the family has an `opsz` axis, cut two instances and switch at ~28px. If it has no axis and no display cut, do not set it above ~40px.

**L9 — A type scale is a ratio, not a list.**
28 distinct sizes rendered across the deck. The declared "four tiers" were fiction. Measured step ratios: 1.348 → 1.179 → 1.444 → 1.080 → 1.250 → 1.220. A 1.08 step (21.6px against 20px) is not a step; the audience reads it as a rendering error.
→ One ratio, ≤10 named tokens, and **inline `font-size` is banned**. This deck carried 33 inline `font-size` declarations and 99 inline `style=` attributes: the system was overridden more often than it was used.

**L10 — Body copy is a design decision, not an inheritance.**
`:where(p, li) { font-size: 1.25rem }` set size and nothing else, so leading came out at 1.8 — the UnoCSS prose default, never a choice — and `strong` inside body inherited a different weight *and* a different colour *and* a different line-height, striping every emphasised paragraph with a muddy navy near-miss.
→ Set size, leading, colour and the `strong` treatment together, in one rule, on purpose.

**L11 — If you never wrote a `::marker` rule you shipped the browser's.**
No `ul`/`li`/`::marker` rule existed anywhere. Result: 20px square glyphs, `padding-left: 0`, marker at 67.6px and bullet *text* at 96.3px — a broken left axis on every bulleted slide.
→ Hang the marker in the margin and align bullet text to the same optical axis as the kicker, or drop markers entirely.

**L12 — `max-width: Nch` plus `text-wrap: balance` cannot widen, so it rags at the wrong place.**
"Five True or False statements." broke as `Five True or / False statements.` — splitting the bound phrase on the slide whose entire job is to introduce a true/false quiz.
→ `ch` caps are a ceiling, not a line-breaker. Any headline containing a bound phrase gets an explicit `<br>` at the meaning break. Pick one convention for terminal periods on display headlines and hold it.

### 1.3 Colour lessons

**L13 — Contrast is arithmetic. Run it before you pick, not after someone squints.**
Measured failures that all passed a build and a screenshot review: white on gold **2.36:1** across 9 slides including two section dividers; bare gold numerals on white **2.36:1** at 89.6px, six times; `--fog: #B9C2CE` 1px borders at **1.80:1**; green `#27AE60` on its own tint **2.52:1** while the paired red was 4.54:1, so the good/bad pair was visually unbalanced — the trap legible, the win faded.
→ Two token families per hue: one for **fills**, one for **type**. Type tokens clear 4.5:1 on every ground they can legally land on. Borders clear 3:1 (WCAG 1.4.11).

**L14 — Never fix a contrast failure with a text-shadow halo.**
The lifted deck compensated white-on-orange (2.73:1) with a triple shadow. Inheriting the compensation inherits the defect.
→ Halo is for type over **photography** only. Over a flat colour, change the colour.

**L15 — Port the architecture, re-derive the palette.**
The lifted deck's dominant surface was a full orange field with white caps on 22 slides. Gold cannot do that job in any direction (white-on-gold 2.36:1, gold-on-cream 2.30:1). The register has to invert: navy becomes the shout field, gold is demoted to accent.
→ When lifting a system across brands, recompute every pairing. A ported palette is a ported failure.

### 1.4 Composition lessons

**L16 — Median content fill is the single best proxy for "does this look amateur."**
Measured content bounding box against slide box across 133 slides: **median 27.8%**, mean 30.3%, 35 slides under 20%, one at 3.3%, median bottom gap 217px of 720. Vertical centring was already correct — the content was simply too small for the canvas.
→ Gate it: median ≥ 55%, no slide below 35%. A slide that cannot reach 35% is two slides that should be one.

**L17 — Never QC only at click 0 on a slide whose first beat is clicked.**
On `two-cols` slides every left-column bullet sat inside `<v-clicks>`, so the *held* state — the one the speaker talks over — was a 13px kicker alone beside a small diagram with 315px of white below it. The QC script's own header argues click 0 is honest because hidden content reserves layout space. That is true of geometry and false of appearance.
→ Shoot click 0 **and** full reveal. Every column carries at least one unclicked element.

**L18 — Measure every asset with PIL before you place it, and check the aspect, not just the width.**
`scene/*.png` is 1920×861 = **2.23:1**, not 16:9. `object-fit: cover` on the 16:9 canvas crops 20.3% — 10.1% off each side, straight through burned-in type. `vsl/*.png` at 1960×1104 = 1.775 is a 0.1% crop and bleeds safely. Under ~1400px wide an asset goes in a card at native aspect, never full-bleed. Two files in `public/images/proof/` are byte-identical (`wall_of_love.png` = `senja_wall_of_love_456_reviews_2026_07_23.png`, same md5) — 878KB and one naming hazard for one asset.
→ Run the dimension sweep before the placement pass, not after the QC.

**L19 — Write the per-slide map before the first slide.**
The reference deck's `_VISUAL_MAP.md` — one row per slide: `id | headline ≤7 words | tempo | emotion | VISUAL | treatment | anim | foot` — produced an 80% treatment-alternation rate and 98% of headlines at ≤7 words. You do not get that writing slides one at a time; you get it by reading the treatment column top-to-bottom and breaking every run of 3. Its bottom section lists every asset too small for its intended treatment, with pixel dimensions.
→ No slide is written before its row exists. Diff map against build before ship; drift is real.

**L20 — Every click is a keypress the presenter must land on a spoken beat, live, for the first time.**
153 slides, 17 chat-wait stops at 20-45s each = 8-12 minutes of unbudgeted dead air, and zero timing marks anywhere.
→ Prefer constructs that cost **zero** advances: a global `clickAnimation`, `v-after`, static diagrams, `AutoFitText`, `Transform`. Put a target clock on every section divider.

### 1.5 Motion lessons

**L21 — The biggest motion risk in a deck is usually already in it. Audit before you add.**
`transition: slide-left` was set once in headmatter and applied to all 153 slides at Slidev's default 0.5s: 152 full-viewport translates. Every pixel moves every frame, so a screenshare encoder cannot use motion vectors, sends a full keyframe repeatedly, and the audience sees smear and judder at Zoom's effective 5-15fps. The golden deck sets `transition: none` globally with `fade` on 12 dividers.
→ Reduction first. Adding motion on top of a bad global transition is optimising the wrong thing.

**L22 — On a live screenshare the cost of motion is paid by the video codec, not the GPU.**
→ Only `opacity` and small `translate`/`scale`, GPU-composited, ≤300ms, on ≤30% of the frame. Anything full-frame and continuous is banned while anyone is speaking. Never animate `width`, `top`, `filter` or `box-shadow` — they force layout/paint every frame.

**L23 — One global preset beats 153 local edits — and check the cascade before you trust it.**
The deck used exactly two constructs (`<v-clicks>` ×22, `<v-click>` ×10, zero modifiers), so one headmatter line retro-fits motion onto all 82 animated slides. But measured: with `clickAnimation: up` alone, `.slidev-vclick-target { transition: opacity 200ms ease }` (specificity 0,1,0) in the deck's own stylesheet beats Slidev's `.slidev-vclick-target.slidev-vclick-anim-fade-in` (0,2,0), so `translate` is set to `0px 20px` but is not in the transition list and the element **teleports**. The `fade-in` keyword is load-bearing.
→ Reach for the global lever first, then verify the computed style, then advance every click.

**L24 — Motion budgets are ratios, and the golden already records ours.**
Golden, 105 content slides: `v-mark` 5 uses, `v-motion` 3 applications, 12 `fade` transitions, recorded in `BUILD_v8.md` as a deliberate ration. Scaled to 153 slides: ~7 marks, ~4 motions.
→ Cap it. Scarcity *is* the mechanism — at 2.7% of slides a giant numeral is an event; at 10% it is a tic.

**L25 — Anything that measures a box once, at mount, breaks when the window changes.**
`v-mark` draws at `show()` and never redraws. Measured: drawn fresh at 1600×900 the annotation spans 1.26× the word width; drawn at 1280×720 and then resized it spans 1.10×, dx off by ~9px, visibly clipping into the word. Verified it does **not** redraw on click-back-then-forward, and does **not** redraw on leaving the slide and returning. Only a full page reload restores it — which mid-webinar means a white flash and a lost click position.
→ This is a **procedure**, not code: go fullscreen and start the share *before* advancing off the holding slide; never toggle fullscreen, resize, or change monitors once the deck is running. Never nest a measuring component inside a `display:none` container — it computes a 0×0 box.

**L26 — Nothing a live deck renders may cross the network.**
The Excalidraw addon dynamic-imports `@excalidraw/excalidraw@0.18.0` from esm.sh inside `onMounted` with a `/* @vite-ignore */`: 5.3s to first paint warm, and with esm.sh unreachable the slide renders the literal words "Failed to render Excalidraw." on stage. The `default` theme also fetches Google Fonts at runtime on every load.
→ Self-host fonts. Pre-export diagrams to SVG and commit them. Mermaid is safe because it renders to inline SVG at **build** time (verified: zero runtime requests on a mermaid slide).

### 1.6 Live-instrument lessons

**L27 — A slide must never claim a fact about the room.**
Three slides asserted the audience's behaviour: printed chat subjects as fact, and printed "I see a mix. Good." while the note admitted the chat may be lopsided and supplied a recovery line the presenter can only use by contradicting his own screen.
→ Print the **question**, perform the **reaction**. Reactions live in notes only.

**L28 — A slide must never spoil its own reveal.**
The demonstration statically bound "Response A → scored a 3 / Response B → scored a 5" seven slides before asking the room to guess which scored a 5 — on the slide the deck's own note calls the load-bearing interaction of the whole webinar. Elsewhere a static 3-row table handed over six numbers the speaker was about to narrate.
→ Any number that is the answer to a later slide is clicked, never static. When a beat is "commit, then be corrected," nothing on screen may pre-answer it.

**L29 — Runtime promises on stage must be achievable from what is written.**
Extracted `SPOKEN:` blocks total 3,149 words ≈ 22.5 min at 140 wpm. The deck says "the next 45 minutes" on stage and "in the last forty minutes" in the recap.
→ Either write the notes up to full verbatim, or change the number. Never leave a figure on stage the deck cannot hit.

**L30 — Slide-ID comments drift from the rendered index; the presenter reads the index.**
Comments run 001→139 with three numbers missing and nine letter-suffixed inserts; the renderer counts 153. Any rehearsal note saying "on slide 44" points at nothing.
→ Generate the ID↔index map from the build and ship it with the cue sheet.

### 2.2 The global click preset — and the cascade patch that makes it real

`clickAnimation: fade-in up` upgrades every existing `<v-click>` / `<v-clicks>` from an opacity blink to a 20px rise + fade, with zero new markup. Both properties are GPU-composited.

**The deck's own line 91 currently kills the translate.** Replace it with this (specificity 0,2,0 / 0,3,0, and later in the cascade — it wins in both directions):

```css
/* 🔴 REPLACES the old `.slidev-vclick-target { transition: opacity 200ms ease; }`.
   MEASURED 2026-08-15: at 0,1,0 that rule beat Slidev's .slidev-vclick-anim-fade-in
   (0,2,0), so `translate: 0px 20px` was set but never transitioned and every reveal
   TELEPORTED. `fade-in` must also stay in the headmatter preset string. */
.slidev-vclick-hidden { opacity: 0 !important; }

.slidev-layout .slidev-vclick-target,
.slidev-layout .slidev-vclick-target.slidev-vclick-anim-fade-in {
  transition: opacity 220ms ease, translate 220ms ease, scale 220ms ease;
}
```

Per-slide override where a hard cut is wanted:



### 2.4 `<VSwitch>` — the Essay A ↔ Essay B swap (slides 089 / 092)

Swaps in place, one click, no layout jump, no new slide. This is the correct component for the "both got A's, one understood the game" beat and it replaces the `_SPEC_visual_law.md` §7.9 proposal to use Magic Move.

```md
<VSwitch :transition="'fade'">
  <template #0>
    <div class="sp-card">
      <div class="sp-waylabel">Response A</div>
      <div class="sp-body mt-2">…opening paragraph, verbatim…</div>
    </div>
  </template>
  <template #1>
    <div class="sp-card">
      <div class="sp-waylabel">Response B</div>
      <div class="sp-body mt-2">…opening paragraph, verbatim…</div>
    </div>
  </template>
</VSwitch>
```

Props (`node_modules/@slidev/client/builtin/VSwitch.ts`): `at` (default `'+1'`), `unmount` (default false), `transition`, `tag`, `childTag`. Slot names are click offsets; ranges work (`#2-4`). Keep slot numbers contiguous from 0.

🔴 **Never put `v-mark` inside a `VSwitch` slot.** With `unmount` false the hidden slot is `display: none`, so a mark measures a 0×0 box.

### 2.6 `v-mark` — 8 uses, one per section, object form only

Doubles as the cheapest fix for the failing G1 visual gate: `deck_gate.py` line 64 counts `v-mark` as a VISUAL. 25 slides are both bare *and* unanimated (04_mechanisms 10, slides.md 7, 05_demonstration 4, 02_pain 2, 01_quiz 1, 08_close 1) — one span fixes both problems on the same slide.

```md
<span v-mark="{ at: 1, type: 'circle', color: '#C5A55A', strokeWidth: 3, padding: 8 }">invisible</span>
<span v-mark="{ at: 2, type: 'underline', color: '#C0392B', strokeWidth: 4 }">a 3</span>
```

### 2.8 Zero-click statics that carry their weight

```md

     Self-corrects if the presentation window differs from the QC render. -->
<div class="sp-h1 sp-onimg">
  <AutoFitText :max="70" :min="42" modelValue="The Back-to-School Game Plan" />
</div>

<!-- Transform: shrink an overflowing block rather than re-typesetting it.
     Default origin is `top left` and will shift a centred block — always pass origin. -->

  <div class="sp-rubric">…</div>
</Transform>
```

`AutoFitText` props: `modelValue`, `max` (default 100), `min` (default 30), units px. Marked `[Experimental]`; it sets `overflow: auto`, so a `min` you have not rendered can produce a scrollbar inside the frame. Render-check the exact string.

### 2.11 DO NOT USE

| Capability | Why it is banned |
|---|---|
| **Magic Move** | Works, and `_SPEC_visual_law.md` §7.9 proposes it for the essay swap. It is a token-level diff engine built for **code**: on prose it re-tokenises and crawls dozens of glyphs across the frame independently, so the encoder cannot use motion vectors and sends a full keyframe every frame — ~800ms of smeared mush on Zoom. It also requires a shiki code fence, which typesets parent-facing essays as monospace. **Use `<VSwitch>`.** |
| **Excalidraw addon** | Installed, and listed in the cheat-sheet. Measured: dynamic-imports from esm.sh in `onMounted`, 5.3s to first paint warm; with esm.sh unreachable the slide renders "Failed to render Excalidraw." on stage. If a hand-drawn diagram is wanted: export to SVG once, commit it, reference with `<img>`. |
| **`view-transition`** | Not in the shipped `transitions.css`. Browser-dependent, unverified. Not eleven days out. |
| **`v-drag` / `<VDragArrow>`** | Authoring tools. Dragged positions are written back into the source markdown — a stray drag during a live share silently edits the deck file. |
| **Scroll / parallax** | The Slidev frame is a fixed 16:9 with overflow clipped. There is no scroll surface; a hand-built version is continuous full-frame translate, the single worst screenshare payload. |
| **`transition: slide-left`** (or any directional) | 152 full-viewport 0.5s translates. This is the defect being removed, not a style choice. |
| **`clickAnimation` without `fade-in`** | Measured: the translate is set but not transitioned and the element teleports. Looks fine in a screenshot; only fails when someone advances a click. |
| **`v-mark` inside `VSwitch` / any `display:none`** | 0×0 bounding box → the mark draws at the wrong size. |
| **`v-mark` + `v-motion` on one element** | The mark measures a box that is still translating. |
| **`<Arrow>` outside `layout: cover`** | Coordinates are hard-coded viewport px against the fixed frame, and absolute children collapse to 0×0 without `layout: cover`. Not worth the fragility here — use `v-mark` instead. |
| **`animation:` on `width`/`top`/`filter`/`box-shadow`** | Forces layout/paint every frame. Transform and opacity only. |

### 2.12 The live procedure (this is part of the motion spec)

`v-mark` draws once at `show()` and never redraws. Measured drift after a 1280→1600 resize: ~9px horizontal, ~13% undersized, clipping into the word; not fixed by clicking back and forward, not fixed by leaving and returning, only by a page reload.

1. Load the deck on the presentation machine **well before 8:00 PM ET**, so all six font files are in cache.
2. Enter fullscreen.
3. Start the Zoom share.
4. **Then** advance off the holding slide.
5. Do not toggle fullscreen, resize the window, or change monitors for the rest of the night.

## 3. THE TYPE SPEC

### 3.1 The decision

**Display: `SED Display` — Merriweather v2.100, variable source, instanced at `wght` 700/900, `wdth` 100, `opsz` 96.**
**Body: `SED Sans` — Manrope v4.504, variable source, instanced at `wght` 400/500/700/800.**

The pairing is kept, the *cut* is fixed. Merriweather stays because 20+ full-bleed VSL and scene frames carry burned-in Merriweather type and any other display face makes every one of them read as a spliced-in second deck. What was actually broken was that the deck shipped a **text** cut (`opsz=32`) and set it at 49-96px with -0.03em tracking. The variable source carries an `opsz` axis from 18 to 144; an `opsz=96` instance is a real display cut with the sidebearings and stroke contrast the sizes below require. Manrope's `wght` axis maxes at **800** — every `font-weight: 900` on a sans element in the current CSS is unbuildable and must go.

Source files (verified on disk):
`/root/ai-os/06_Clients/supported/05_assets_and_deliverables/vsl_v3_render/assets/fonts/Merriweather.ttf` (wght 300-900, wdth 87-112, opsz 18-144)
`/root/ai-os/06_Clients/supported/05_assets_and_deliverables/vsl_v3_render/assets/fonts/Manrope.ttf` (wght 200-800)

### 3.2 Build the faces — exact, runnable, verified

Current `public/fonts/` ships 5 faces at **813KB**, of which the two Merriweather files are 2,384 glyphs each, completely unsubsetted, 365KB and 359KB. The command below produces **6** faces at **75KB total** — verified by running it.

```bash
set -e
DECK=/root/slidev-webinars/supported/back_to_school_2026_08_10
SRC=/root/ai-os/06_Clients/supported/05_assets_and_deliverables/vsl_v3_render/assets/fonts
OUT=$DECK/public/fonts
UNI="U+0020-007E,U+00A0,U+00B7,U+2013,U+2014,U+2018-201D,U+2022,U+2026,U+2192,U+2713,U+00A9,U+00AE,U+00B0"
mkdir -p "$OUT" && cd "$(mktemp -d)"

# Display serif — the opsz=96 DISPLAY cut. Nothing here is set below 44.8px.
for W in 700 900; do
  fonttools varLib.instancer -q -o d_$W.ttf "$SRC/Merriweather.ttf" wght=$W wdth=100 opsz=96
  pyftsubset d_$W.ttf --unicodes="$UNI" --layout-features='kern,liga,calt,lnum,tnum' \
    --flavor=woff2 --output-file="$OUT/SEDDisplay-$W.woff2"
done

# Body sans — 400 / 500 / 700 / 800. Manrope's axis MAXES AT 800; there is no 900.
for W in 400 500 700 800; do
  fonttools varLib.instancer -q -o s_$W.ttf "$SRC/Manrope.ttf" wght=$W
  pyftsubset s_$W.ttf --unicodes="$UNI" --layout-features='kern,liga,calt,lnum,tnum' \
    --flavor=woff2 --output-file="$OUT/SEDSans-$W.woff2"
done

rm -f "$OUT"/Merriweather-*.woff2 "$OUT"/Manrope-*.woff2
ls -l "$OUT"
```
